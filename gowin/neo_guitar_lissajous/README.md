# 四弦演奏驱动的居中莉萨如显示，完整音频 FULL

本工程把已验证的三音色 FULL 音频链与到货的 480×272 RGB 屏整合。
Top 为 `neo_guitar_lissajous_top`，器件 `GW5AT-LV60PG484AC1/I0`，Device B。
图形直接在屏幕原始像素上绘制，中心为 **(240,136)**，X/Y 半径均为 94 像素；
主体约 188×188，包含边缘光晕后约 194×190。底部保留四根弦的信息区。
没有低分辨率画布放大，因此不会出现之前 4 倍放大的块状效果。

## 演奏与图形的关系

每根弦拥有一条曲线：`x=240+94*sin(该声部的音高 DDS 相位)`，
`y=136+94*sin(220 Hz 参考相位)`，截取约 21.33 ms 的轨迹。
共同参考让单音、不同品位以及复音之间有明确的频率比例关系。

- 品位矩阵只选音，实际拨弦才启动声音和曲线。
- 四音同时演奏时，四条曲线叠加，交叉处混色；底部按弦编号列出品位、音高 Hz 和音量条。
- 四种色相保持相对区分，同时整体缓慢循环；曲线有空间渐变、抗锯齿、光晕和上一帧相位的淡残影。
- 接收的是发声链真实的 `phase_inc`，保留原来的 20 ms 换品滑音，不直接跳到品位表的目标频率。
- 松品后保留当前发声音高，跟随原阻尼收声。延音开启时，声音与曲线继续保持；结束后曲线消失。
- 已接受的拨弦通过事件计数传到显示域，触发短暂增亮。振幅条和亮度来自每声部 PCM 峰值。
- 当前仍默认固定力度 2，因此峰值显示代表声音包络，不是已标定的物理拨弦力度。

这里展示的是四个声部的**音高 DDS**，并非 FFT 测量值，也不是每个音色全部模态的 XY 混合。
哇音半倍频、钢琴非整数模态及自动五度和声仍完整保留在声音中；画面用四条主音高曲线表示四根弦。
同音声部可能重合，底部编号和信息区仍能区分它们。

## 完整保留的声音与控制

四声部、每声部 32 分量，钢琴、明亮弦音、哇音 V4、击弦起音、
原模态 ROM、包络、采样率、定点精度、合唱、延音、混响、五度和声、立体声和 PT8211 输出保持原配置。
新增显示仅旁路读取数据，没有音频背压，也没有修改音色核心或采样表。
原 FFT/频谱源文件及工程入口继续保留；本固定引脚工程采用莉萨如显示。

| 底板按键 | 功能 |
| --- | --- |
| KEY0 / USER_BUTTON1 / AA13 | 钢琴 → 明亮弦音 → 哇音，循环 |
| KEY1 / USER_BUTTON2 / AB13，短按松手 | 合唱开/关 |
| KEY1，长按约 1 秒 | 五度和声开/关，在后续拨弦时生效 |
| KEY2 / USER_BUTTON3 / Y12 | 无效果 → 延音 → 轻混响，循环 |

三键全部用于原演奏功能。本工程配置后自动初始化。
独立 LCD 演示中的 KEY0 复位、KEY1 图案、KEY2 暂停定义不适用于本工程。

## 接线与下载

1. 保持已有 J13 品位矩阵、J8 MCP3208、PT8211/功放和 MS5351M CLK2=12.288 MHz 接线。
2. LCD 保持已成功测试的 J5 40-pin 接线，**J17 的 1–2 针使用跳帽**。
   它关闭共享 RGB 引脚的 CH569 供电；本工程不使用 CH569。屏幕直接接 RGB，无需 HDMI。
3. V22 的 50 MHz 板载时钟用于显示，V13 的 12.288 MHz 用于音频。
   显示没有另建像素时钟逻辑域，50 MHz 除 6 得 8.333333 MHz DCLK。
4. 打开 `neo_guitar_lissajous.gprj`，或在仓库根目录运行：

```powershell
gw_sh.exe gowin/neo_guitar_lissajous/build.tcl
```

5. 下载本工程的 **`impl/pnr/neo_guitar_lissajous.fs`**。初测使用 SRAM Program/Configure。
   这是同时包含完整音频和显示的固定引脚位流。

`constraints/neo_guitar_lissajous.cst` 固定了 52 个互不冲突的端口。
三枚用户键为 Bank 9、LVCMOS15；其余沿用已有板级 LVCMOS33。
RGB666 对应 J5 的 R2–R7、G2–G7、B2–B7；每色低两位在底板接地。
DCLK=L19/J5-30，HSYNC=N20/32，VSYNC=L15/33，DE=L14/34，背光使能=P20。
VDD 与 DISP 保持底板提供的 3.3 V。
背光仍沿用已调试硬件；其恒流值须与实际屏规格匹配，FPGA PWM 不能替代恒流电阻匹配。
GT911 触摸接口暂未接入本显示程序。

时序沿用用户成功显示彩条的方案：H=4/39/480/8，总 531；V=4/8/272/8，总 292；
刷新约 53.745 Hz。RGB、DE、同步信号在 DCLK 下降沿输出，距上升采样沿约 60 ns。

## 资源与流水线

原音频 FULL 已使用 112/118 BSRAM、111/118 DSP。
本显示改用两条 512×12 bit 行缓存，每个像素保留四声部各 3 bit 覆盖度；
另外使用单端口正弦和反正弦 ROM。整个显示只需 4 个 BSRAM，不建立全屏帧缓存。

每行用反正弦找参考波的交点，再由一个共享乘法器和正弦 ROM 计算四声部的 X 坐标。
跨行交点连成细线，分数坐标提供抗锯齿；覆盖度更新流水线每个时钟写一个像素。
读当前行和提前绘制下一行并行，行缓存只在消隐期交换。
跨行坐标选择与边界计算分为两级；字体先寄存卡片坐标，固定字符位置采用区间判断，
无需除法/取模；字形另一级查找，颜色输出为四级流水线。
频率比除法器四声部共享、在帧消隐内完成；颜色插值采用移位，没有降低任何音频计算精度。

12.288 MHz 与 50 MHz 之间用 400 bit 保持数据的请求/应答邮箱：
两级同步 toggle，额外等待一个接收时钟后整组捕获。快照在帧消隐内发布，音频持续运行。
内部 setup/hold 与实际资源统计由 `check_result.py` 检查并写入 `verification.json`。
外部屏采样 setup/hold 未获得完整规格，因此没有编造外部输出延迟约束；60 ns 稳定时间已做 RTL 检查。

最终布局布线结果（Gowin V1.9.12.03，Device B）：

| 项目 | 结果 |
| --- | --- |
| Logic / Register | 31791 / 13981 |
| BSRAM | 116 / 118，其中音频 112、显示 4 |
| DSP | 113.5 / 118 |
| 音频 Fmax，实际工作 12.288 MHz | 13.512 MHz |
| 显示 Fmax，实际工作 50 MHz | 51.360 MHz |
| Setup / Hold 违例、Latch | 0 / 0、0 |

扫描线最慢 2328 / 3186 时钟。资源和时序余量有限，后续新增频谱需重新分配显示资源；
当前实现没有减少音频模态数量或计算精度。

## 验证和实物初测

```powershell
./gowin/neo_guitar_lissajous/run_sim.ps1 -ModelSimBin '你的 ModelSim/win64'
./gowin/neo_guitar_lissajous/run_gate_check.ps1 -ModelSimBin '你的 ModelSim/win64' -GowinHome '你的 Gowin/IDE'
python gowin/neo_guitar_lissajous/check_result.py
```

实际矩阵扫描和 SPI ADC 模型驱动四弦演奏、换品、重拨、延音/松品、三音色及音效。
带显示和原音频 FULL 的声部 PCM、DDS、生命周期、矩阵/ADC、DAC 位流、功放和 LED
连续 **6,271,622 个音频时钟完全一致**，无音频计算 deadline miss。
原三音色独立整数参考测试另比较了 212,000 样本，钢琴与 FULL 模态测试也通过。
扫描线独立解析模型检查 1,632 行、最高品四音和多种相位，最慢结果见 `verification.json`，每行预算 3,186 时钟，无丢行。
屏幕端完整帧检查 480×272、消隐、8.333 MHz 像素周期、信号稳定时间和缓存切换。
门级检查使用 Gowin 原语模型，比较综合网表的实际 LCD 引脚及 DAC 串行输出与 RTL，
并把当前网表 SHA-256 写入验证记录。只过滤原语模型未使用 RAM 位宽分支的已知诊断，
自身 RTL/网表/测试台的告警或不一致均导致检查失败。
修正后网表已比较 951,405 个有效像素和 6,528 帧 DAC 输出，全部一致；
其中包含 1,597 帧哇音半速包络输出。
