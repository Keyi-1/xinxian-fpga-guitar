### 上板单音噪声修复（2026-10-04 22:29）

用户反馈 WAV 正常，但上板单音像机械颤动。新增实际 GW5A 原语的综合后仿真，
在 PT8211 的 BCLK 上升沿解码两声道数据；旧网表 792 帧中有 476 帧与 RTL 不同。
追踪发现原包络 `(b-a)*fraction` 被映射到 DSP 预加器后，ROM 幅度位宽收缩的符号扩展
引入了额外 16384 偏移。随 fraction 变化，它产生约 93.75 Hz 的错误幅度锯齿，
可以解释 WAV 正常而上板听起来嘈杂的差异。

当前使用两个显式无符号乘积 `a*(512-fraction)+b*fraction`，在原流水线位置寄存后除以 512。
整数舍入结果与原正确 RTL 完全一致，不改变音色参数、击弦、混响或音高。
重新导出的两份 WAV SHA256 与修复前一致。
修复后 **6696 个真实 256/4 分频的 DAC 帧与综合前 RTL 逐比特一致**，覆盖 F4 单音、
三音色区的三/四音、击弦、全部房间延迟及复位；另外 69 项常规回归通过。
这是综合后功能仿真，没有施加布局布线 SDF 或代替再次上板试听。

本次修正版另存为 `build/piano/neo_guitar_main_piano_interp_fix.fs`，

## 音源实现

`rtl/synth/piano_voice_core.v` 是一个独立的钢琴声部，四个实例并行使用：

- 8 个独立 32 位模态相位累加器。先对 phase increment 乘实测频率比，再累加。
  第一分音比值严格为 1.0，保持原音符基音；高于 Nyquist 的模态被抑制。
- 各分音使用不同的观察幅度包络，256 帧，每帧间隔 512 个音频样本，进行逐采样线性插值。
  它沿用用户认可样音的湿录音特征，不声称已识别干琴弦的真实阻尼。
  1.6 秒以后平滑衰减，最迟约 2.73 秒结束，无固定 Sustain 平台。
- 每次拨弦播放最长 2048 个样本、约 42.7 ms 的短瞬态。
  素材来自各单音第二次起音，先去掉拟合的主要分音，再带通和加短窗。
  它是近似瞬态残差，包含录音/建模残差，不能等同于完全分离的真实琴槌声音。
- 四级力度作用于整体增益；本阶段尚没有多力度层钢琴采样或完整的力度亮度标定。
- 松品的 Q24 阻尼系数沿用约 21 ms 的快速阻尼时间尺度，低电平仍能保持细小衰减步进。
  相同采样上的拨弦优先于松品。
- 快速重拨用约 1.3 ms 的短连续性修正，避免直接将原来的非零样本切为零。
  同时保持每根弦的固定窄声像，不因新音色区或拨弦顺序跳到另一侧。

每声部以时分流水线完成模态、包络、击弦和增益计算，一个音频帧使用 61 个参考时钟边沿，
低于物理主工程的 256 周期采样间隔。包络插值共用一个 ROM 读取端口，避免两份 ROM 副本。
32 位 DDS、主要乘法和增益都分级寄存，音频计算全部在 FPGA 内完成。

### 音区与音高

三个音色区是 C/E/G 参考特征的初始迁移，中心按常用编号 C4/E4/G4 划分，
更低/更高音区分别沿用端点音色区；同一次拨弦中音色区不随滑音重新选择。
这是有限参考数据下的初始配置，不代表已经逐音标定 D3～C5 全音区。

原参考录音的实际主要频率接近 C5/E5/G5；本次 RTL 试听采用乐器实际可演奏的
**C4/E4/G4（约 261.6/329.6/392.0 Hz）**，比参考录音低一个八度。
这是选用的测试音符不同，钢琴音源没有给当前乐器整体移调。
原 `note_phase_inc.mem` 与滑音取值范围均保持原样。

### 立体声与空间

四根弦从高到低的左右权重为：

| 弦 | 左 | 右 |
|---|---:|---:|
| 1 | 160/256 | 192/256 |
| 2 | 168/256 | 184/256 |
| 3 | 184/256 | 168/256 |
| 4 | 192/256 | 160/256 |

各声道固定除以二，保留混音余量。每个音同时存在于两侧，不再根据近邻音龄降低和弦中的某个声部。
钢琴模式绕过旧的减拍频权重和独立声道音效，使用一个公共三延迟反馈空间。
干声 7/8，两个不同延迟抽头各 1/32，反馈边为 1/2；这是轻量模拟空间，不是库乐队混响的复制。
RAM 使用独立读写地址推断 SDPB，解决 GW5AT 不支持所推断 SP 写模式的问题。
复位时用填充计数屏蔽旧 RAM 内容，PA 行为仍由原板级逻辑控制。

## 参数与切回

`rtl/config/guitar_config.vh`：

| 宏 | 本分支默认 | 用途 |
|---|---:|---|
| `BOARD_USE_PIANO` | 1 | 物理主工程启用钢琴音源 |
| `BOARD_PIANO_HAMMER_ENABLE` | 1 | 加入短击弦瞬态，置 0 可做起音对照 |
| `BOARD_PIANO_ROOM_ENABLE` | 1 | 公共轻混响，置 0 可试听该模型的直接输出 |
| `BOARD_USE_HARMONIC` | 0 | 钢琴关闭后仍可使用原可选谐波核 |
| `BOARD_ANTI_BEAT_ENABLE` | 1 | 钢琴模式忽略此权重；原音源模式才使用 |

每次改宏后重新构建。`BOARD_USE_PIANO=0` 恢复前一版主工程音源/混音。
再设置 `BOARD_ANTI_BEAT_ENABLE=0`，可恢复与原成功全链路基线相同的正弦混音。
通用 `guitar_audio_top` 和共享链的 `USE_PIANO` 默认仍为 0；只有物理主入口默认启用。
FULL/LCD 的现有可选 32 分量路径保留，没有在本次改成钢琴版本。

## ROM 与离线准备

运行期间只需要已纳入工程的四个 ROM：

- `mem/piano_ratio.mem`：24 个 Q20 频率比。
- `mem/piano_phase.mem`：24 个固定初始相位。
- `mem/piano_envelope.mem`：3×8×256 个幅度节点。
- `mem/piano_hammer.mem`：3×2048 个 16 位有符号瞬态样本。

`mem/piano_profile.json` 保存原始 WAV 哈希、来源起音、处理说明、量化余量和 ROM 哈希。
模态幅度总和上界约为 PCM16 的 16384，击弦峰值上界 2048；四音混音保留静态余量。
Python 仅用于离线提取与验证。原 WAV、NumPy、SciPy 均不是 FPGA 播放的依赖。

如需重新提取，先运行参考分析，再运行：

```powershell
& 'E:\anaconda3\python.exe' tools/generate_piano_assets.py
```

修改 ROM 后需要重新仿真和构建；本版本只有三个有限音色区，不应当作完整钢琴采样器。

## 实际 RTL 试听与检查

文件在 `build/piano/`，都是原始 RTL PCM16、48 kHz、立体声；没有逐文件归一化、额外混响或重采样。

- `rtl_piano_hammer.wav`：当前带击弦起音版本，6 秒。
- `rtl_piano_body.wav`：相同钢琴模态与公共空间，关闭击弦起音。
- `rtl_piano_hammer_comparison.wav`：不带起音 6 秒，静音 0.4 秒，带起音 6 秒。
- `rtl_piano_attack.png`：实际数字输出的起音包络与频谱对照。

顺序：C4、E4、G4 各自弹一次，再弹两次 C4/E4/G4 三和弦，最后加入 G3 低音的四音合奏。
音色模型参数、声像、混响和力度保持一致，差异只来自击弦开关。
导出仿真使用 64/1 采样/DAC 分频加速，模态与包络方程仍按 48 kHz 的样本数运算；
默认物理工程 256/4 分频另有真实时钟集成检查。

独立 Python 数值参考使用不受硬件字长限制的整数运算，验证 32000 个采样点、
三个音色区、四级力度、同采样拨弦优先、滑音、松品、跨音色区快速重拨以及带/不带击弦。
另外检查公共 RAM 复位无旧尾音、三/四音不削波、采样期限和主工程默认输入时序。
原正弦兼容路径仍与保留的实测平铺源逐周期比较。
