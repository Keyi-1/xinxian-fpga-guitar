# MPU-6050 持琴姿态与音色切换设计方案

日期：2026-10-14。状态：未来设计，尚未实现或进行实物验收。

本文件由本次侧边讨论独立生成。仅新增设计文档，不修改 RTL、CST、工程配置、现有音源、构建产物或 Git 提交状态。
用户已购买图示 GY-521 / MPU-6050 模块，并确认：**无论丝印称 KEY0 还是 KEY1，现有负责音色切换的那颗按键继续负责音色切换**。

## 1. 结论与目标

方案合理，可以由 FPGA 直接读取 MPU-6050 实现。首版用加速度计判断稳定方向，用陀螺仪判断是否正在快速移动；不必先实现欧拉角、四元数、航向识别或 DMP 固件。

“姿态设定默认音色，按键保留手动选择”作为基本交互：

| 稳定姿态 | 自动进入时的默认音色 | 现有音色切换键 |
| --- | --- | --- |
| 琴面向上、近似平放 | 钢琴 | 继续切换音色，不因平放而失效 |
| 琴面离开水平、琴颈未接近竖直，类似斜抱吉他 | 拨弦／当前明亮弦音 | 下一次短按切为哇音；继续按仍沿循环选择 |
| 琴颈朝上、接近竖直，类似竖抱琵琶 | 琵琶，音源完成后启用 | 继续切换音色 |
| 移动、倒置、过渡区或数据异常 | 保持当前选择 | 始终可以手动切换 |

自动选择只在“确认进入一个新的稳定姿态”时发生一次。处于同一斜抱姿态时，不能每隔 10 ms 将按键选出的哇音重新改成拨弦；真正离开再重新进入斜抱状态时，才重新选择默认拨弦音色。

它识别的是空间姿态，不能证明琴已接触桌面，也不能区分“举直琴颈的吉他”和“同样朝向的琵琶”。需要通过回差、稳定时间及自动开关处理这些边界。

## 2. 按键名称与选择优先级

文档统一使用 **音色切换键 K_TONE**。当前源码的实际对应关系：

- 顶层输入：`USER_BUTTON1_n`，低有效。
- `guitar_effect_buttons.v` 中的功能输入：`key_timbre_n`。
- 当前循环：钢琴 → 明亮拨弦 → 哇音 → 钢琴。
- GPIO 球位：AA13，Bank 9、LVCMOS15；这是现有按键，不能当作新增传感器的 3.3 V GPIO。

不依据用户口头的 KEY 编号修改其他按键。合唱／五度和声、无效果／延音／混响的按键职责保留。

推荐保留原循环顺序，不强制按姿态限制可用音色。在斜抱状态，默认明亮拨弦，第一次 K_TONE 自然切到哇音；继续按可切到钢琴。这样既满足“斜抱先拨弦、再按切哇音”，又保留现有按键的完整职责。若以后需要“吉他姿态只在拨弦与哇音之间循环”，作为可选设置，不能默认改变现有循环。

实现时需要一个最终音色状态的所有者：K_TONE 必须从最终 `selected_timbre` 的当前值继续循环。
不能让按键模块保留一个与自动选择不同步的私有计数器，否则自动选到拨弦后第一次按键可能仍选拨弦，而没有切到哇音。
未来可把现有去抖模块的合格按下事件交给选择策略模块，效果键仍在原模块处理；不复制第二套音色键去抖，不产生两个相互竞争的音色状态。

琵琶听感验收通过后，循环扩为：钢琴 → 明亮拨弦 → 哇音 → 琵琶 → 钢琴。未完成时保持原三音色循环。

同一音频边界的控制优先级建议为：模式退出／显式停止 → 手动 K_TONE → 已确认的姿态事件。姿态事件与按键同到时，记录新姿态，但采用按键选择，不延后一帧再覆盖它。

定义三个控制状态：

| 状态 | 姿态事件的作用 | K_TONE 的作用 |
| --- | --- | --- |
| AUTO | 新稳定姿态选择默认音色 | 手动循环；选择保持到下一次新姿态或用户重新启用 AUTO |
| MANUAL | 只显示姿态 | 按原循环切换 |
| LOCK_AUTO | 不自动换音色，后台继续测姿态 | 仍可手动循环；此处“锁定”仅锁自动控制 |

AUTO／MANUAL／LOCK_AUTO 用触控设置切换，不借用现有效果键的长按，也不增加 K_TONE 长按功能。当前 K_TONE 在合格按下时触发切换，保留该触发习惯，不为分辨长短按而改成抬起触发。

初次安装、未校准或传感器故障时默认 MANUAL，开机仍是钢琴。校准后由用户启用 AUTO。演奏模式可以使用 AUTO；游戏模式默认不受姿态影响，但 K_TONE 仍可手动切音色，用户可以主动为游戏启用 AUTO。菜单中只监测姿态，不发声、不触发拨弦。

## 3. 已购模块可以确认什么

图片能确认模块标注为 GY-521 / MPU-6050，排针信号包括 VCC、GND、SCL、SDA、XDA、XCL、AD0、INT。接线以**到货模块丝印**为准，不能把商品照片从左到右的位置当作永久针序。

MPU-6050 是三轴加速度计加三轴陀螺仪的六轴 IMU，主机接口为 I²C。没有内置磁力计，不能独立提供绝对航向；商品说明中的九轴能力及 SPI 信息不能直接当作该模块已具备的功能。[TDK 产品页](https://product.tdk.com/en/search/sensor/mortion-inertial/imu/info?part_no=MPU-6050)、[官方产品规格书，第 9 节](https://product.tdk.com/system/files/dam/doc/product/sensor/mortion-inertial/imu/data_sheet/mpu-6000-datasheet1.pdf)

图片不能确认到货模块稳压器的准确型号、其压差、上拉电阻的电源连接，以及 VLOGIC 的实际连接。因此暂不宣布“任何 GY-521 都可以直接用 5 V 并连接 FPGA”。

模块 VCC 商品标注 3～5 V，是模块输入的说明；芯片 VDD 规格为 2.375～3.46 V，I/O 参考 VLOGIC，VLOGIC 不得高于 VDD。不能把芯片的 REGOUT 内部稳压节点误当作板载稳压器输出。[官方产品规格书，第 6.3、6.5 节](https://product.tdk.com/system/files/dam/doc/product/sensor/mortion-inertial/imu/data_sheet/mpu-6000-datasheet1.pdf)

供电决策顺序：先只接模块 VCC/GND，以 3.3 V 输入检查板载稳压器输出及芯片供电；再核对 SDA/SCL 空闲电压和上拉去向。如果 3.3 V 输入使芯片供电不足，再根据稳压器资料决定供电／转换方法，不能通过盲目改成 5 V解决通信故障。信号线与 FPGA 接通前，确认两端通信电平兼容；必要时使用双向开漏电平转换。

## 4. 接线与总线选择

| GY-521 信号 | 初版用途 |
| --- | --- |
| VCC | 按上一节确认后的模块电源 |
| GND | 与 FPGA 共地 |
| SCL、SDA | I²C，总线端只输出 0 或高阻，配兼容电平的上拉 |
| AD0 | 接 GND，7 位地址 0x68 |
| INT | 首版可不接，读取数据就绪状态 |
| XDA、XCL | 外部辅助传感器接口，本方案留空 |

AD0 为高时主机地址是 0x69；它不是 SPI 数据脚。WHO_AM_I 预期仍为 0x68，与 AD0 取值无关。[官方规格书第 9.2 节](https://product.tdk.com/system/files/dam/doc/product/sensor/mortion-inertial/imu/data_sheet/mpu-6000-datasheet1.pdf)、[官方寄存器表第 4.32 节](https://invensense.tdk.com/wp-content/uploads/2015/02/MPU-6000-Register-Map.pdf)

### 4.1 独立调试阶段：独立 I²C

建议先做传感器独立验证工程，SCL/SDA 单独布线，便于测量，不先接入音源和 GT911。

候选为 J8-11/Y21、J8-12/Y22：当前 CST 未占用这两个球位，现有仓库连接矩阵将其列为 3.3 V Bank 8 的 PMOD 信号。现有 ADC 使用 J8-5～8，矩阵已移到 J13。这只是候选，实施时必须重新核对底板／核心板原理图、Bank 电压、排针方向及 SDRAM1／摄像头复用；本文件没有冻结 CST。

不能从 J9 随便再占两根线：J9 已有四个诊断 LED 和标准 I²S；J6 原生触控启用后释放的 U21 只有一根，不足以构成独立 I²C。过时的 PMOD 品位矩阵分配不能作为当前接线依据。

### 4.2 集成版优先评估：与 GT911 共用一个主机

考虑当前逻辑资源紧张，集成版优先评估由**一个 FPGA I²C 主机和仲裁器**服务 GT911 与 MPU-6050。两设备地址不同，GT911 的 0x5D／0x14 与 MPU 的 0x68／0x69 不冲突。共享时将 MPU 的 SCL/SDA并到 J6 同名网络，GT911 的 RST、INT 继续独立控制；MPU 不借用 GT911 的 INT 或 RST。

共享前必须确认模块上拉电压、并联上拉等效阻值和总线电容。底板已有上拉，不默认给每个模块再加一组；共享只是电气兼容后的一种资源复用选择。

现有 `rtl/input/i2c_register_master.v` 固定发送两字节寄存器指针，适合 GT911；MPU 使用一字节指针，不能只换设备地址就直接复用。未来需参数化 `register_address_bytes=1/2`，保持 GT911 两字节模式行为不变，并支持至少 14 字节突发读。GT911 清除 0x814E 仍保持读报告后清零的顺序。

单主机调度规则：事务中途不抢占；GT911 报告读取与状态清除作为连续任务；给 MPU 保留每 10 ms 一次数据读取机会；超时释放总线。按 100 kHz 估算，GT911 最坏按 200 次/秒读报告并清状态约占 31% 总线时间；MPU 100 次/秒读 14 字节约占 15%，若加 200 次/秒状态轮询约占 7%。加 START/STOP、同步和拉伸余量，按约 55～60% 预算，再实测触控延迟。

共享总线意味着传感器把 SDA/SCL 拉死时也可能影响触控，不能宣称电气故障已经隔离。两类请求均需独立错误状态，失败时保留手动演奏；若影响触控验收，再保留独立总线，代价是先腾出更多逻辑资源。

## 5. MPU-6050 读取与初始化草案

目标：100 kHz I²C、约 100 Hz 有效采样、加速度 ±4 g、陀螺仪 ±250°/s。用于静态分类和运动门控，不积分航向。

| 顺序 | 寄存器 | 初始写值／动作 | 意图 |
| --- | --- | --- | --- |
| 1 | 0x75 WHO_AM_I | 读取，检查 0x68 | 确认设备身份，不仅检查 ACK |
| 2 | 0x6B PWR_MGMT_1 | 0x80，等待复位完成 | 设备复位；100 ms 是初始保守等待值 |
| 3 | 0x6B PWR_MGMT_1 | 0x01 | 退出睡眠，选 X 轴陀螺仪 PLL |
| 4 | 0x6C PWR_MGMT_2 | 0x00 | 六轴保持启用 |
| 5 | 0x1A CONFIG | 0x03 | DLPF 配置 3 |
| 6 | 0x19 SMPLRT_DIV | 0x09 | 在该 DLPF 配置下由 1 kHz 分至 100 Hz |
| 7 | 0x1B GYRO_CONFIG | 0x00 | ±250°/s |
| 8 | 0x1C ACCEL_CONFIG | 0x08 | ±4 g，8192 LSB/g |
| 9 | 0x23 FIFO_EN、0x6A USER_CTRL | 0x00 | 初版不使用 FIFO、DMP、辅助主机 |
| 10 | 0x37 INT_PIN_CFG、0x38 INT_ENABLE | 0x00、0x01 | 启用数据就绪状态，INT 可保持未连接 |

初始化关键值回读，等待起动稳定后开始校准。表内配置据官方寄存器说明整理，实际驱动仍需检查保留位、复位状态和实物返回值；不能以“有 ACK”替代量程设置成功。[官方寄存器说明，4.2～4.5、4.15～4.16、4.28～4.32 节](https://invensense.tdk.com/wp-content/uploads/2015/02/MPU-6000-Register-Map.pdf)

建议每 5 ms 轮询 0x3A 的数据就绪位，有新数据时从 0x3B 连续读取 14 字节：Ax/Ay/Az、温度、Gx/Gy/Gz。每个量为高字节先到的有符号 16 位值；完成整包且无错误才发布。温度先留作诊断，不控制音高或音量。读就绪状态而非反复把同一包计为新样本。[官方数据接口说明，第 7.16、7.18、9 节](https://product.tdk.com/system/files/dam/doc/product/sensor/mortion-inertial/imu/data_sheet/mpu-6000-datasheet1.pdf)

数据接口建议：`sample_valid`、六轴数据、样本时间戳、递增序号、`imu_ready`、错误码、数据年龄。NAK、总线卡死、ID 错误、饱和以及数据不新鲜均不得被当作“0 g／平放”。

## 6. 安装与校准

传感器固定在琴身硬结构上，靠近琴身中部，避免长悬臂和仅靠松软泡棉固定。固定螺丝、排线应有机械应力释放；安装方向不能只依据商品照片。

定义琴身坐标：X 从琴身指向琴颈，Y 横向，Z 垂直琴面、指向正面。模块轴通过轴交换与符号取反映射到琴身坐标，初版不允许任意角度松散安装，避免为补偿安装方向新增三维矩阵乘法。

静止时，琴面向上平放应使 Z 约 +1 g；琴颈朝上竖抱应使 X 约 +1 g。这里采用加速度计的静态输出极性，实际以校准确认，不能平方后丢掉正负方向。

校准步骤：

1. 独立采集六轴，确认轴、符号与量程。
2. 保持真正水平的琴面向上状态，采集至少 256 个有效样本，约 2.56 s；期间运动、饱和或漏包则重来。
3. 陀螺仪均值作为零偏；加速度 X/Y 的期望为 0，Z 的期望为 +8192，得到粗零偏。不能将三个均值全部减成 0，把实际重力也消掉。
4. 录下平放、实际斜抱、实际竖抱各至少 5 s 的数据，检查它们是否被初始分类窗口覆盖。
5. 若安装／器件偏差较大，升级为 ±X、±Y、±Z 六面校准，分离偏置与比例误差；用离线工具拟合固定点参数，FPGA 复用串行乘法运算，不新增专用 DSP。

初版每次上电重新完成校准或加载显式选择的已校准常量；是否存入 Flash 后续另设计，不能随意占用当前 FPGA 配置 Flash 或改变启动方式。

## 7. 滤波与运动门控

首版处理的是稳定姿态，陀螺仪用于拒绝快速动作，不做累计角度积分。这样不会为了保持航向而引入陀螺仪积分漂移，也不依赖磁力计。

加速度一阶低通：`f = f + ((a - f) >>> 3)`，有效更新约 100 Hz，时间常数约 75 ms。内部保留 4 位小数，避免反复整数右移造成明显死区；第一次有效包直接初始化滤波器。陀螺仪先减零偏，运动门控看当前值，避免只看过度平滑的数据漏掉冲击。

以下均是调试起点，不是已测阈值：

| 门控 | 建议起点 | 不满足时 |
| --- | --- | --- |
| 新包／完整包 | 序号更新且整包成功 | 不累积稳定时间 |
| 数据年龄 | 最近有效包 ≤30 ms | 取消候选，保持已选音色 |
| 加速度幅度 | 原始校正包约 0.8～1.2 g，滤波包也合理 | 判为运动／无效 |
| 陀螺仪角速度 | 每轴绝对值 <25°/s | 取消候选 |
| 相邻包加速度变化 | 每轴变化 <0.12 g | 取消候选 |
| 数值饱和 | 未接近 16 位量程边界 | 判为运动／无效 |

拨弦、快速抬琴、敲击桌面可能让门控短暂失败，只取消正在累积的候选，不把已确认姿态改成另一种。恒定平移加速度可能绕过简单幅度门控，故这仍是稳定姿态分类，而非任意动作下的精确姿态测量；需要升级时再考虑加速度与陀螺仪融合。

## 8. 无角度计算的三姿态分类

令滤波后的校正值为 x、y、z，`S=x²+y²+z²`。方向比例用平方和比较实现，不在 FPGA 内计算 atan2、平方根或浮点除法。

| 姿态 | 进入条件示例 | 已进入后的保持条件示例 |
| --- | --- | --- |
| 平放 FACE_UP | z>0 且 z²/S ≥0.883，琴面距水平约 ≤20° | z>0 且 z²/S ≥0.750，约 ≤30° |
| 竖抱 UPRIGHT | x>0 且 x²/S ≥0.883，琴颈高于水平约 ≥70° | x>0 且 x²/S ≥0.750，约 ≥60° |
| 斜抱 GUITAR | z²/S ≤0.500，琴面已离水平约 ≥45°；x²/S ≤0.750，琴颈未超过约 60°；x≥-0.15 g | z²/S ≤0.671；x²/S ≤0.821；x≥-0.25 g |
| 未明确 UNKNOWN | 不满足任一窗口、倒置或运动 | 保持已确认状态和手动音色 |

斜抱允许琴颈接近水平，避免把真实的水平持吉他漏掉。它仍是可调窗口，需要按实际琴面与身体的夹角校准。向下竖放 x≈-1 g 不能触发琵琶；琴面朝下 z≈-1 g 不能触发钢琴。

Q15 常量示例：0.883022→28935、0.750→24576、0.500→16384、0.671010→21988、0.821394→26915。比较 `z² << 15` 与 `S × 28935`，不要先用整数相除后丢掉精度。

校正值至少按有符号 17 位处理，平方保留 34 位，三个平方之和至少 36 位，乘 Q15 常量的比较中间量使用足够宽的无符号类型，例如 54 位。必须显式符号扩展、处理绝对值溢出；不能沿用音频模块的 24 位宽度直接截断。

一个串行移位加法运算单元复用计算原始／滤波平方和及阈值乘积。100 Hz 下每帧有约 500000 个 50 MHz 时钟，计划给分类算术不超过 1000 个时钟的预算；该预算属于设计目标，尚未综合。无需占用新增 DSP。

## 9. 稳定姿态状态机

分别保存 `candidate_pose`、`stable_pose`、有效候选起始时间和上次自动切换时间。

1. 门控不合格时取消候选计时，已确认姿态保持；严重异常另标记健康状态。
2. 当前姿态仍满足“保持条件”时，不产生新的姿态进入事件。
3. 超出当前保持区后评估进入条件；不能把剩余所有方向默认归为斜抱。
4. 同一有效候选持续至少 500 ms 才确认。使用时间戳与最大包间隔检查，不能只累计 50 个可能不连续的包。
5. 自动音色选择之间至少相隔 1 s；这只限制自动事件，不阻止 K_TONE。
6. 确认新姿态后更新 `stable_pose`，发一次 `pose_enter`。UNKNOWN／MOVING 本身不选择音色。

短暂摇晃且回到同一姿态不重新设置默认音色。进入另一种明确姿态后再回到斜抱，重新默认拨弦。若希望“离开斜抱到未知区、在未知区停很久再回来”也恢复默认，可以设置独立的重新进入政策；首版推荐未知区不重置手动选择，避免反复覆盖哇音。

预计动作停稳后响应约 0.6～0.8 s，取决于低通收敛及门控；1 s 自动切换间隔可能再增加等待。不能把 100 Hz 采样率当作 10 ms 自动切换延迟。

## 10. 跨时钟与选择事件

传感器、滤波、分类和触控调度在 50 MHz 域；音色选择的最终仲裁在 12.288 MHz 音频域。

姿态进入事件用保持数据加请求／确认握手传输，携带姿态、建议音色和递增事件号。不分别同步多位音色编号，也不使用仅一个系统时钟宽的脉冲直接跨域。事件可合并为最新未确认目标，手动输入优先；同一事件号只处理一次。

姿态事件只更新 `selected_timbre`，不得生成 note_on、note_off、force_release，不改变品位、拨弦事件、力度、DDS 目标、滑音、PA 使能或 I²S／PT8211 时钟。

模式退出的既有停止流程保留。重新进入演奏模式时，MANUAL 保留手动选择，AUTO 可按当前已确认姿态选择默认；传感器离线时仍可进入并演奏。

健康策略：有效包中断超过 100 ms 时关闭自动选择、清候选，保留当前音色和所有声音，K_TONE 正常工作；后台约 1 s 周期重试。恢复后先重新建立至少 1 s 有效数据，重新分类，不以恢复后的第一包立即抢占音色。
恢复也不能撤销用户在故障期间用 K_TONE 作出的选择；同一姿态不重发默认选择，只有后续的新姿态进入事件或用户主动重新启用 AUTO 才允许改变。

## 11. 原音尾声保护：两阶段实施

### 11.1 现有结构的限制

当前 `four_voice_piano_audio_core.v` 只有一套共享的 timbre/rock 平滑控制，四个 `piano_voice_core` 每个采样帧都更新 `frame_timbre/frame_rock`。直接接入姿态选择会改写正在衰减的旧音。

另一个限制是 `piano_stereo_effects.v` 中音色相关的软限幅／drive 位于左右声道混音之后，且参数来自共享音色控制。**只锁存每个声部的音色编号，不足以保证后续全局处理不再改写旧音。** 当前命名为 rock 的限幅模块实际使用 `timbre_blend`，实现前应按真实控制连接审查，不能按模块名字猜它只作用于哇音。

### 11.2 验证版：自动切换等待音源空闲

第一版姿态联动不改音源，只让自动目标等待所有声部结束、无待处理 note_on 且音频流水线排空后，再通过原平滑控制切换。开始采用至少两个采样边界的排空检查，并核对各流水线 valid 的实际延迟。

持续演奏或延音状态下，自动切换可以一直待命，界面显示“待切换”，不强制结束旧音，也不能通过缩短包络制造空闲。K_TONE 仍沿用现有实时平滑切换；按键操作取消当前待命的自动目标，避免松手后突然被它覆盖。

这一版只验证姿态功能和交互，不宣称“下一次拨弦立即新音色、所有旧音维持原音色”已经完成。

### 11.3 正式版：起音锁存与音色相关处理隔离

目标行为：选择改变后，下一个真实起音使用新音色；其他弦的旧音继续原音源包络、频率与音色。每弦仍对应一个声部；再次拨同一弦重触发该声部，是既有行为，不额外保留同弦的第五个尾音声部。

每声部在 note_on 时锁存音色 enum，整个自然尾音保持该选择；相位初始化、模态比例、包络表、击弦／拨弦激励及颜色相关参数都必须由这个锁存值选取。不能在起音时锁一个编号，却在后续 LOAD 状态继续看全局 rock 选择。平滑／连续性处理仍保留，但不能把新选择的过渡混合值注入其他旧声部。

后混音非线性需单独设计：`clip(a+b)` 不等于 `clip(a)+clip(b)`，不能简单把原软限幅移到每个声部前面后宣布音色完全不变。推荐把声部按锁存音色分组，保留原声像、增益和组内混音算术，对需要相应处理的音色组复用原左右声道处理单元，再合并进入公共合唱与混响。

要求：所有活跃声部为同一旧音色、控制已稳定时，分组路径必须还原原有后混音处理和该组的力度策略；混合音色时，一个新音色不能改变另一个组的软限幅参数。合唱／混响继续共享并保留延迟缓冲，模式变换不重置效果。用户主动操作效果键造成的效果变化属于原功能，不承诺各声部独立锁存全部效果。

现有音源预算约 233/256 个参考时钟，但这不是完整“音源＋音效＋PCM转换＋发送器”的剩余预算。复用音色组处理增加的周期必须沿整条 valid 链测量，验证每帧样本准时送给两路输出，不把“还有 23 拍”直接当作可全部使用的余量。

不复制一套完整音源，不删除钢琴模态、明亮／哇音分量、合唱、混响、和声或降低音频采样率。若不能在资源和时序内实现，正式版暂不启用，保留验证版的待切换策略。

## 12. 琵琶音色开发边界

姿态识别可以先完成，但当前没有经过验收的琵琶音源。`PIPA_AVAILABLE=0` 时，竖抱显示“琵琶待开发”，实际音色保持当前选择，不把现有钢琴或拨弦音色改名冒充琵琶。

音源完成后才将竖抱进入事件映射到 PIPA，并扩展 K_TONE 循环。建议复用现有每声部 32 槽调度与乘法路径，增加独立参数集，而非增加第五声部或复制四套新核心。

声音路线：实时噪声／拨弦激励、弦振动及琴体模态、快速衰减的高频分量、力度控制的起音亮度和响度。先制作单音音区／力度试听，再做四弦复音。不可直接播放预录琵琶 PCM；参数拟合是否符合赛题另按条款确认，本文件不作比赛合规结论。

滚奏和轮指若以后增加，应作为新的演奏／触发设计，不默认由“竖抱”合成额外音符，避免把姿态检测变成自动演奏。

## 13. 资源预算与先决优化

已核对的上一份完整验证快照为触控游戏 U21 转接版，资源仅用于规划：Logic 57717/59904、Register 23386/60780、CLS 29767/29952、BSRAM 95/118、DSP 115.5/118；音频 Fmax 14.610 MHz，系统 Fmax 51.156 MHz。J6 直连版及后续版本以其最终构建报告为准，本文件不替主线程认定新构建结果。

该快照 CLS 占约 99.38%，不能因尚有 BSRAM 就判断能直接添加全部逻辑。传感器、分类和仲裁目标是新增 DSP=0，初版不新增专用 BSRAM；实际 LUT、寄存器、CLS 开销尚未综合，不能承诺一次就放得下。

建议依次评估：共享 I²C 主机；只传必要姿态状态；复用已有快照的保留位，避免再复制宽 CDC；收紧事件消费掩码与时间寄存器；研究垂直消隐期内单缓冲更新能否替代游戏布局双缓冲。后两项必须以“有效显示之前计算完成”和原像素对照为证据，不能为省资源引入撕裂。

状态显示优先复用已有 ASCII 字模，例如 P/G/U、A/M/L 和待命标志；不先增加大字号页面或角度绘图。逐声部锁存及琵琶阶段分别综合，保存启用／禁用功能的资源差值和时序，不把资源估计当作实测报告。

## 15. 实施顺序与验收

| 阶段 | 内容 | 通过条件 |
| --- | --- | --- |
| A | 模块电源、总线、独立六轴读取 | 确认量程、轴／符号、ID；保存实际供电和总线测量 |
| B | 三姿态、运动门控与回差，仅显示状态 | 实际三种姿态均覆盖；动作和倒置不误认 |
| C | AUTO／MANUAL／LOCK_AUTO、空闲自动切换 | 斜抱后按键切哇音保持；重新进入斜抱默认拨弦；手动职责不丢失 |
| D | 逐声部锁存及音色相关处理隔离 | 新拨弦使用新音色，旧声部参数／PCM不被姿态事件改写 |
| E | 琵琶单音、音区、力度与复音 | 主体和起音听感验收、合规检查、资源和周期预算通过 |
| F | 触控、游戏、显示、音频整合 | 总线延迟、长时间演奏、静态时序和两路样本连续性通过 |

必须覆盖的测试：平放／斜抱／竖抱每种反复进入至少 20 次；阈值边界停留 60 s；正常拨弦 5 min；快速抬琴、摇晃、轻碰桌面和反向竖放；人工构造重复包、漏包、NAK、卡 SCL 和拔传感器。

测试 K_TONE 与姿态事件同到、持续按品不拨弦、空弦续音、四弦同拨、延音状态长尾、同弦重触发、模式退出。故障不能生成音符、切掉尾音、改变品位或关闭功放。

数字对照分层进行：功能关闭时与原工程逐样本／引脚一致；功能启用但姿态未变化时不引入漂移；正式版对旧声部的起音锁存参数和进入音效前 PCM 做独立对照；所有声部为同一旧音色时核对原混音／音色处理。新音加入后的最终混音本来会变化，不能把它误当作“旧声部被改写”，也不能用混音听感替代旧声部对照。

最终验收同时报告每模块资源、完整链路周期、无丢样／重复样本、48 kHz 输出、3.072 MHz 标准 I²S、无未布通网络和 setup/hold 结果。单独传感器项目通过不等于满资源主工程可以直接加入。
