# 芯弦 FPGA 电子吉他：配置修改计划

> 本计划描述后续实施时需要创建或修改的配置，不在本轮生成 Gowin 工程、RTL、约束、IP 或仿真占位文件。

## 1. 修改目标与保护范围

当前可见工程 `高云仿真教程/gowin_prj/gw138.gprj` 是面向 `GW5AST-138B` 的 FIFO 教程，顶层仅包含 FIFO 读写端口。它不是芯弦工程的可迁移基线。

实施时必须遵守：

- 保留 `高云仿真教程/` 及其综合产物不变；
- 在 `xinxian-fpga-guitar/` 下创建全新的 60K 工程；
- 不复制教程中的 `fifo_top`、旧 `top.v` 或 `gw138.cst`；
- 引脚只能从实际 NEO Dock 版本的官方原理图和官方完整约束表中选择；
- LCD 型号未冻结前，不写死 LCD 数据、初始化和背光引脚；
- 每次配置变化都需要对应仿真、综合报告和上板证据。

## 2. 配置变更总览

| 配置域 | 当前状态 | 目标状态 | 主要动作 |
| --- | --- | --- | --- |
| 项目目录 | 只有 138K FIFO 教程 | 独立芯弦工程 | 新建 `gowin/`、`rtl/`、`constraints/`、`ip/`、`sim/`、`mem/` |
| 目标器件 | `GW5AST-138B` | `GW5AT-60B` | 重建 `.gprj`，选择正确 PN 和 Device Version B |

| 引脚约束 | 仅旧 `sys_clk=V22` | NEO Dock 完整约束 | 从官方约束复制并裁剪，完成复用冲突表 |
| 时序约束 | 未形成整机约束 | 多时钟域 SDC | 定义 50 MHz、12.288 MHz、PLL 和异步时钟组 |

| 音频接口 | 无 | PT8211 16-bit LSBJ | 新建格式化、位时钟和功放控制配置 |

## 3. Gowin 项目迁移

### 3.1 新项目文件

计划创建：

```text
gowin/xinxian_mega60k.gprj
```

器件配置必须是：

```xml
<Device name="GW5AT-60B" pn="GW5AT-LV60PG484AC1/I0">gw5at60b-002</Device>
```

实施人员需要在 Gowin EDA Commercial V1.9.12.03 中再次核对 GUI 显示的：

- Series：GW5AT；
- Device：GW5AT-60B；
- Part Number：GW5AT-LV60PG484AC1/I0；
- Package：PBG484A；
- Speed：C1/I0；
- Device Version：B。

若 GUI 生成的内部器件 ID 与示例中的 `gw5at60b-002` 不同，以 V1.9.12.03 实际生成结果为准，不手工伪造 ID。

### 3.2 FileList 组织

`.gprj` 只纳入：

- 可综合 Verilog-2001 文件；
- 目标板 `.cst` 与 `.sdc`；
- Gowin IP 生成文件和 wrapper；
- 综合需要的 `.mem`／初始化文件。

不得纳入：

- SystemVerilog testbench；
- ModelSim 工作库、`.wlf` 和转储波形；
- `build/`、`impl/`、`temp/` 等生成目录；
- 离线生成脚本及其缓存；
- 旧 FIFO 教程源文件。

### 3.3 综合配置

首次建立工程时记录并版本化以下设置：

- 顶层模块名与 Verilog 语言版本；
- 综合优化目标、FSM 编码和 RAM/DSP 推断策略；
- 未使用引脚、双用途引脚和配置引脚策略；
- bitstream 压缩、SRAM 下载和外部 Flash 下载设置；
- 所有 warning 的处置清单。

不得仅保存 `.gprj.user` 作为团队共享配置；个人路径和 GUI 状态应排除在版本库外。

## 4. 顶层端口计划

建议的逻辑端口组如下，实际 FPGA 管脚在原理图审查后填写：

| 端口组 | 信号 | 方向 | 数量 | 备注 |
| --- | --- | --- | ---: | --- |
| 系统时钟 | `sys_clk_50m` | 输入 | 1 | 板载系统时钟，实际管脚复核 |
| 音频时钟 | `audio_clk_12m288` | 输入 | 1 | 外接 3.3 V CMOS 有源晶振 |
| 复位 | `rst_n` | 输入 | 1 | 按键或上电复位，异步断言同步释放 |
| 琴颈扫描 | `fret_scan[3:0]` | 输出／高阻 | 4 | 每次只激活一行 |
| 琴颈返回 | `fret_sense[7:0]` | 输入 | 8 | 外部约 10 kΩ 上拉 |
| ADC SPI | `adc_cs_n/sclk/din/dout` | 混合 | 4 | MCP3208，3.3 V |
| 音频 DAC | `dac_bclk/lrck/din` | 输出 | 3 | PT8211 LSB-justified |
| 功放 | `pa_en` | 输出 | 1 | 极性按原理图实测复核 |
| 用户键 | `key[2:0]` | 输入 | 3 | 音色、合唱、延音／混响 |
| LCD 数据 | `lcd_r/g/b[7:0]` 或 `[5:0]` | 输出 | 18–24 | 内部按 RGB888；物理位宽按底板版本和转接板核验 |
| LCD 时序 | `lcd_pclk/de/hsync/vsync` | 输出 | 4 | 屏幕定型后启用 |
| LCD 控制 | `lcd_rst/init/bl*` | 混合 | 待定 | 取决于屏幕和转接板 |
| 调试 | `debug_gpio[*]` | 输出 | 待定 | 仅 DEBUG 构建 |

### 4.1 引脚分配步骤

1. 下载与实际 NEO Dock PCB 版本对应的官方原理图和 All PIN Constraints。
2. 先锁定板载固定外设：50 MHz、用户键、PT8211、功放、RGB 接口。
3. 标注 RGB 与 CH569 HSPI、PMOD、DVP、40P 排针之间的复用关系。
4. 为 4×8 矩阵、MCP3208 和 12.288 MHz 晶振选择未冲突的 3.3 V GPIO。
5. 检查每个 IO Bank 的 VCCIO，不允许把外部 5 V 信号接入 FPGA。
6. 检查时钟输入是否使用适合的全局时钟管脚；若非全局管脚，必须评估专用时钟资源与时序。
7. 对长线传感输入设置合适的上下拉和驱动强度；不要用最大 DRIVE 作为默认值。
8. 形成“连接器针号—原理图网络名—FPGA ball—顶层端口—IO 标准”五列对照表。
9. 完成设计审查后再写入 `tang_mega_60k_neo.cst`。
10. 用万用表和最小点灯／回读工程逐组验证，不能一次接入全部外设后再排错。

## 5. 时钟与 SDC 计划

### 5.1 时钟域

| 时钟域 | 目标频率 | 来源 | 主要模块 |
| --- | ---: | --- | --- |
| `clk_sys` | 50 MHz | NEO Dock | 上电、低速控制、PLL 输入 |
| `clk_compute` | 建议 100 MHz | 50 MHz PLL | 声部、谐波调度、音效、FFT 控制 |
| `clk_audio_ref` | 12.288 MHz | 外部有源晶振 | 音频整数分频与 FIFO 读端 |
| `dac_bclk` | 1.536 MHz | 12.288 MHz ÷8 | PT8211 16-bit×2 声道 |
| `sample_tick` | 48 kHz | 12.288 MHz ÷256 | 样本提交节拍 |
| `clk_pixel` | 待定 | 独立 PLL | 800×480 并行 RGB，按面板时序冻结 |

音频 `sample_tick` 建议作为时钟使能而不是新的大范围 fabric clock；PT8211 输出寄存器应使用专用、可约束的时钟路径。

### 5.2 SDC 必需内容

计划在 `constraints/timing.sdc` 中加入：

- 50 MHz 输入时钟，周期 20 ns；
- 12.288 MHz 输入时钟，周期约 81.380208 ns；
- PLL 生成时钟和 LCD 像素时钟；
- 计算域、音频域、像素域之间的异步时钟组；
- MCP3208 SPI 输入／输出延迟；
- LCD、PT8211 输出时序；
- 仅对经过结构化同步器或异步 FIFO 的路径设置 CDC 例外；
- 同步器寄存器属性与 CDC 报告检查。

禁止用全局 `set_false_path` 掩盖未经同步的跨域路径。每条例外必须在配置计划或代码注释中说明结构依据。

### 5.3 时钟验证门

- PLL `lock` 前保持全系统静音与复位；
- 音频参考失锁或 FIFO underflow 时输出零样本，不输出旧数据；
- 对 BCLK、LRCK 和实际采样率进行示波器测量；
- LCD 开启后重新检查全部音频时钟域 WNS；
- `FULL` 构建所有时钟域 WNS ≥0。

## 6. 集中参数文件计划

计划创建：

```text
rtl/config/guitar_config.vh
```

该文件只包含可综合常量、构建宏和位宽，不存放大规模 ROM 数据。建议参数分组：

```verilog
// Build
BUILD_MINIMAL / BUILD_FULL / BUILD_DEBUG

// Audio
SAMPLE_RATE_HZ       = 48000
INTERNAL_PCM_BITS    = 24
DAC_BITS             = 16
VOICE_COUNT          = 4
HARMONICS_MAX        = 32

// Input
FRET_STRINGS         = 4
FRET_COUNT           = 8
VELOCITY_LEVELS      = 4
ADC_CHANNELS_USED    = 4

// Display
FFT_SIZE             = 1024
SPECTRUM_BARS        = 32     // FULL 基线，可改为 64
DISPLAY_FPS          = 30
```

还需要定义但必须由仿真或样机标定确定的参数：

- 矩阵扫描率、积分去抖门限；
- 各弦 ADC 基线、噪声门限、4 级力度阈值；
- 峰值保持释放、再触发死区、串扰判定窗口；
- 滑音时间和 phase increment 斜率限制；
- 两套音色的 Attack、Decay、Release；
- KEY3 开启后的 Release 延长倍数；
- 合唱延迟、LFO、深度和干湿比；
- 多抽头延迟长度、反馈和干湿比；
- 软削波拐点与输出总增益；
- FFT 缩放、柱分组、平滑和峰值下降速度；
- 上电静音与按键切换淡入淡出时间。

## 7. ROM 与离线查表

计划由 Python 3 工具生成以下文件：

| 文件 | 内容 | 生成输入 | 验证 |
| --- | --- | --- | --- |
| `note_phase_inc.mem` | 4×9 个基频相位增量 | A4=440、48 kHz、累加器位宽 | 频率误差报告 |
| `sine_lut.mem` | 四分之一或整周期正弦表 | LUT 深度、幅度位宽 | 最大误差、THD 仿真 |
| `harmonics_classic.mem` | 经典音色×4 力度的幅度／衰减 | 音色参数表 | 频谱与包络图 |
| `harmonics_rock.mem` | 摇滚音色×4 力度的幅度／衰减 | 音色参数表 | 频谱、软削波前后图 |
| `hann_1024.mem` | 1024 点 Hann 窗 | 系数位宽 | 与浮点参考误差 |
| `spectrum_map.mem` | FFT bin 到 32／64 柱映射 | Fs、FFT 点数、柱数 | 边界覆盖检查 |

生成工具必须输出机器可读 ROM 和人可读摘要，包括量化格式、最大误差、时间戳和输入参数哈希。禁止手工修改生成后的 `.mem`；修改源参数后重新生成。

## 8. 传感配置计划

### 8.1 琴颈矩阵

实现前先冻结电气极性：

- 选择扫描线低有效或高有效；
- 据此统一 32 个二极管方向；
- 非活动扫描线必须高阻，不与活动线对推；
- 外部上拉／下拉与 Verilog 逻辑极性保持一致；
- 通过单键、同弦多键、跨弦多键和全释放向量验证。

品位解析输出必须包含原始 `fret_mask[3:0][7:0]` 与编码后的 `fret_id`。优先编码规则为第 8 品到第 1 品；全零表示空弦候选状态。

### 8.2 MCP3208 与力度标定

MCP3208 计划配置：

- VDD/VREF 使用干净的 3.3 V，模拟地与数字地按前端 PCB 设计汇接；
- 四路单端输入；
- SPI 模式按数据手册实现，并由 testbench 检查命令和采样边沿；
- 总轮询率 ≥40 kS/s；
- 包络保持时间必须大于完整四通道轮询时间；
- 首版四级力度输出为 2-bit，并与 `pluck_valid` 分离。

建议标定流程：

1. 静止采集每弦噪声和偏置；
2. 每弦分别重复轻、较轻、较重、重拨；
3. 保存峰值分布，不用单次样本定阈值；
4. 为四根弦分别生成三条分级边界和独立触发门限；
5. 用未参与定阈值的重复样本验证分类稳定性；
6. 调节串扰窗口和相对峰值判定，重新验证快速扫弦；
7. 把最终参数写回配置源文件并生成标定报告。

## 9. 音频配置计划

### 9.1 声部和调度

- 四根弦固定映射到四个声部；
- 每声部最多 32 个逻辑分量；
- 声部并行，声部内部允许流水线和分时乘法；
- 调度器必须暴露 `cycles_used`、`deadline_miss` 和样本计数；
- `FULL` 最坏 128 分量时仍在 20.83 μs 内完成；
- 至少一个验收音符明确配置 `harmonic_count=32`。

### 9.2 数值格式

在编码前建立位宽预算表，至少覆盖：

- 相位累加器；
- 正弦 LUT 输出；
- 谐波幅度和衰减系数；
- 单分量乘积；
- 32 分量累加；
- 四声部混音；
- 效果反馈状态；
- FFT 输入与各级缩放；
- 24→16 bit 饱和舍入。

每个截位点都需要说明舍入、截断或饱和规则。禁止依赖 Verilog 隐式有符号扩展。

### 9.3 PT8211 输出

PT8211 wrapper 的固定配置：

- 48 kHz；
- 16-bit 双声道；
- 二进制补码、MSB-first、LSB-justified；
- 左右声道发送同一单声道样本；
- BCLK=1.536 MHz；
- 不生成 MCLK；
- 上电、PLL 未锁定、FIFO 异常时发送零样本；
- `PA_EN` 极性以实际 NEO Dock 原理图和上板测试为准。

不要继续沿用“24-bit I²S 直接驱动板载 Codec”的旧描述。24-bit 只表示内部处理精度。

## 10. 显示配置计划

LCD 型号冻结后执行：

1. 收集数据手册、FPC 表、初始化代码和背光要求；
2. 取得实际 NEO Dock 版本对应的官方原理图与连接器表，确认颜色总线究竟为 RGB666（18 bit）还是 RGB888（24 bit）；产品页、部分官方示例及流传原理图的表述并不完全一致，禁止仅凭商品标题分配 24 根数据引脚；
3. 验证 LCD 的 RGB 模式、电平、FPC、扫描方向和 NEO Dock 接口是否物理兼容，必要时设计转接板；
4. 内部颜色保持每通道 8 bit；若物理接口为 RGB666，则在显示输出 wrapper 中对每通道舍入或截取高 6 bit；
5. 将精确分辨率、porch、同步极性和 PCLK 写入显示配置；
6. 生成像素 PLL 并添加 SDC；
7. 先运行彩条与坐标网格，再接入频谱；
8. 使用逐像素绘制生成背景、32 柱、峰值和状态文字；
9. 验证约 30 FPS，音频 FIFO 不掉样；
10. 若改用 540×960 候选屏，必须独立评审分辨率、旋转坐标、驱动初始化和帧率资源。

首版不配置 DDR3 帧缓存。若后续启用 DDR3，需要作为独立变更重新评审时钟、带宽、IP 和启动时间。

## 11. ModelSim 配置计划

计划创建：

```text
sim/modelsim/compile_libs.do
sim/modelsim/compile_rtl.do
sim/modelsim/run_unit.do
sim/modelsim/run_full.do
sim/modelsim/wave_debug.do
```

### 11.1 仿真分层

- 纯 RTL 单元仿真不依赖 Gowin 库；
- IP wrapper 默认绑定行为模型；
- 发布前再运行包含 Gowin IP 仿真库的配置；
- testbench 使用 SystemVerilog，自检、断言和 scoreboard 必须自动给出 PASS/FAIL；
- `wave_debug.do` 只用于排错，不能代替自检。

### 11.2 最低回归集合

1. 4×8 矩阵扫描、鬼键和最高品位优先；
2. MCP3208 SPI 命令、四通道轮询和力度分级；
3. 演奏事件顺序、快速扫弦和再触发死区；
4. 4×9 音高表和频率误差；
5. 滑音、不重启 Attack、最后品释放；
6. 单声部 32 分量和 128 分量最坏调度；
7. 两音色×四力度的包络与频谱黄金向量；
8. 四声部饱和混音；
9. 合唱、反馈延迟稳定性和旁路淡变；
10. PT8211 10,000 帧协议检查；
11. 1024 点 FFT 与浮点参考对比；
12. 多时钟 FIFO underflow／overflow 注入；
13. 内部延迟计数与 deadline miss 检查；
14. `MINIMAL`、`FULL`、`DEBUG` 三档编译检查。

## 12. 构建档位配置

### MINIMAL

- 单声部；
- 4～8 个谐波；
- 固定测试事件或一根弦输入；
- PT8211 输出；
- 无 FFT、LCD、合唱和混响；
- 用于 2026-09-22 首次上板。

### FULL

- 4 声部；
- 每声部最多 32 个逻辑分量；
- 4×8 琴颈、4 路压电、4 级力度；
- 经典／摇滚、软削波、合唱、延音／轻混响；
- 1024 点 FFT、默认 32 柱、并行 RGB 显示（物理 RGB666/888 按实物配置）；
- 内部 ≤5 ms、整机 ≤10 ms；
- 唯一最终验收档位。

### DEBUG

- 在 MINIMAL 或 FULL 上增加观测；
- 输出触发、样本提交、FIFO 状态和 deadline GPIO；
- 保留 GAO 探针映射；
- 允许降低调试构建 Fmax，但不得用 DEBUG 报告代替 FULL 时序报告。

## 13. 实施顺序与变更门

| 顺序 | 配置工作 | 完成条件 |
| ---: | --- | --- |
| 1 | 重建 60K `.gprj` | 正确器件空顶层可综合 |
