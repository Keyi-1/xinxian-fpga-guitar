# 曲谱与双接口传输

Windows 1.2.0 和 Android 0.3.0 使用相同的 XG3 v3 协议，配套 [当前双接口 FS](../releases/fpga/neo_guitar_touch_game.fs)。Windows 为 DEBUG-USB2、115200/8N1；Android 为 JDY-23、9600/8N1、FFE0/FFE1。蓝牙发送采用 20+12 字节分片、至少 35 ms 间隔。

## 曲谱是什么

曲谱记录音符的开始、持续时长、音高、弦路和力度。音频由 FPGA 逐样本实时合成。Windows 的“电脑试听”是帮助核对旋律与节奏的参考合成，音色以琴上实际输出为准。

Android 支持原始 `.bin`；Windows 支持 `.xgscore`、CSV 和配套 `.bin + .json`。裸 BIN 不包含显示标题和完整的曲目元数据，Windows 使用配套 JSON 提供这些信息；Android 在应用中选择推荐音色。当前板端协议没有标题字段，导入后屏幕显示 `USER n`。

约束：MIDI **50～79（D3～G5）**，最长 10 分钟；四路 lane=0～3，力度 velocity=0～3。客户端在上传前检查排序、同弦重叠及事件密度；同一弦的起音至少间隔 12000 个样本，同一弦在 108200 个样本窗口内最多 8 条事件。不同弦可以同时起音。时间基准为 48 kHz，不是毫秒。

五槽共用 2048 条事件存储，其中 703 条为默认曲库保留，**1345 条供运行时导入**。默认 1 茉莉花、2 Seven Nation Army 短 riff、3 情歌主旋律，4/5 待导入。导入可覆盖目标槽显示内容，复位恢复默认。

两端附带生日快乐歌 25 条、我不难过 564 条、City of Stars 491 条，共 1080 条，事件数据跨端一致。这三首客户端示例与 FPGA 上电默认曲库是两组内容。

## 一次上传

1. 进入主页/选曲页，客户端连接、HELLO 握手，再读取五槽目录。
2. 选择曲谱、目标槽、推荐音色：0 钢琴、1 明亮弦音、2 哇音。
3. 客户端依次发 BEGIN、逐条 DATA、COMMIT，固定 32 字节帧含 CRC32；收到明确应答后继续。
4. FPGA 校验格式、容量、整曲 CRC 和实际 RAM 读回结果，完成跨时钟域目录原子提交。
5. 客户端查询目录核对提交，在琴上选择对应 USER 槽试听。

两路 UART 接收与帧收集器并行，一个协议核按完整帧轮询两路，分别保留会话、序号、响应缓存和错误计数。一次 BEGIN 获得写入所有权，另一端查询可继续、写入返回 BUSY。相同序号的重试使用缓存应答，避免重复执行写入。

## 常见情况

| 提示 / 现象 | 处理 |
| --- | --- |
| Windows 没有 COM | 检查 DEBUG-USB2 数据线和系统串口设备，刷新后选择正确 UART 端口 |
| 手机已连上但握手失败 | 核对当前双接口 FS、FFE0/FFE1、J8 TX/RX 交叉、共地及 9600 波特率 |
| BUSY | 等待另一端上传结束，或回到可导入的空闲界面后重试 |
| NO_SPACE | 五槽共享空间不足；替换时旧曲在新曲提交前仍占空间，不能只按最终条数估算 |
| 提交结果未知 | 保持供电，先查询和试听，按客户端提示人工核对；同样的条数不能证明内容相同 |
| 断电后 USER 曲目消失 | 正常：导入数据在运行时 RAM；Flash 只保存默认曲库与 FPGA 配置 |

命令行编谱与上传入口为 `tools/compile_p2_score.py`、`tools/upload_game_score.py`，可用 `--help` 查看参数。事件编码和校验实现位于 `tools/game_score_v2.py`，XG3 客户端位于 `tools/game_score_upload.py`。
