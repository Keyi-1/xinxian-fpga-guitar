# 钢琴击弦：移除预录 PCM，保留模态主体

## 赛题依据与范围

用户提供的《全国大学生嵌入式芯片与系统设计竞赛 2026 选题指南（高云半导体）》
第 13 页、选题二基础要求 3，要求根据实时演奏指令逐音逐样本生成音频，
并明确禁止直接播放预录 PCM、预置推流及整段录音触发。
同页基础要求 2 允许加法合成、FM、物理建模等方案；第 14 页要求现场以
频谱和 RTL 证明实时合成、无预录回放。

旧版 `piano_hammer.mem` 三组各 2048 点来自录音残差，属于本次移除的回放链路。
片段短、在 FPGA 读取并混入合成声音，都不足以避开该禁止条款。
本版所有击弦样本均在 FPGA 内实时计算，生产工程不再包含残差表。
保留模态频率、阻尼与幅度参数，是对指南所允许加法合成/物理建模的解释；
文件没有明确禁止离线录音分析识别参数。这是本次设计依据，不是对整个工程
所有赛题要求的认证，也不把旧式 ROM 回放改名为“物理建模”。

## 保留哪些音色与功能

基线为 `fb574a4`，保留三音区钢琴的 8 个主要模态、相位种子、频率比、
256 个稀疏幅度观测及线性插值。32 个 DDS 分量、亮弦及 wah 的全部频率/
幅度/自然衰减参数，以及力度、滑音、自动五度、重拨连续性、声像、合唱、
轻混响、延音、PCM 转换和 PT8211 算术均沿用基线。
稀疏幅度包络不是音频波形；声音必须经过实时频率相位累加和正弦计算才能生成。

品位依旧只改音高，松品滑向空弦并继续自然衰减；只有真实拨弦重置起音。
左侧彩条、圆周真实频谱、中央莉萨如与其亮度渐暗模块均未改变。
钢琴前 42.67 ms 的击弦波形有意改变，无法在移除录音回放的同时承诺逐样本不变。
独立 A/B 仿真比较瞬态结束后的钢琴主体及纯亮弦/wah，要求它们逐样本一致。
音效会响应新起音，其数学算法没有改变。

## 实时瞬态模型

每声部维护一个非零 32 位 xorshift 状态。每个音频样本推进三次，产生三个
有符号 16 位创新量，分别经过四级 `state += (input-state)>>2` 低通滤波，
再激励三个阻尼二阶谐振器。低通采用移位加减、保留全部音源分量，
使击弦高频滚降接近参考，避免白噪声使起音偏沙；计算流水线延迟四个样本。
低通的加减器也按时钟复用：在模态 0、1、2 的 LOAD/ENV_B/INC/PHASE
分别更新第 4、3、2、1 级，读取尚未更新的低一级历史。
这与同拍更新四级的每样本结果相同，完整立体声 PCM 哈希保持一致。
四声部使用不同初始种子；
静音时随机状态也继续推进，每次拨弦得到新的激励，不重播固定噪声片段。
复位则可以完全重复计算过程，便于调试。

对每一频带：

```
y[n] = (noise[n] >> shift) - ((a1*y[n-1] + a2*y[n-2]) >> 14)
band[n] = y[n] - y[n-2]
a1 = round(-2*r*cos(2*pi*f/48000) * 16384)
a2 = round(r*r * 16384)
```

三频带输出求和乘以计算生成的“慢指数 − 快指数”包络，形成快速起音与慢衰减。
慢指数每样本减少 `slow>>10 + slow>>11`，快指数减少 `fast>>5 + fast>>6`。
1664 样本以后额外减少 `slow>>6`，2048 样本停止混入。
包络由少量寄存器、移位和加减运算生成，没有 2048 点时序表。
输入激励、滤波历史、输出和随机状态全在寄存器中，不能从常量表复原录音。

三个音区各保存 3 对滤波系数、3 个噪声移位数和 1 个起始包络标量。
中心频率/阻尼与初始能量离线拟合旧瞬态的频谱统计和 RMS，
并未拟合/保存逐时刻波形、相位噪声序列或滤波器状态轨迹。
`mem/piano_hammer_model.json` 记录这些参数及来源；运行时不读取 JSON。
综合使用 `rtl/config/piano_hammer_coeffs.vh` 中的常量。

## 固定点与资源复用

- 系数：有符号 17 位，Q14；滤波历史：有符号 18 位。
- 共享乘积：有符号 35 位，两个反馈乘积先扩展至 36 位再求和与移位。
- 包络：24 位递推，取高 15 位作为 Q15 增益。
- 三频带和限制在有符号 18 位，最终瞬态限制为 ±2048 PCM16 单位，
  与旧版的峰值余量相同，再进入原来的力度、释放及混音运算。
- 滤波内部限幅为保护极端输入；属性测试要求测试音符没有触发内部限幅。
- 末尾 16 样本检查 ≤2 PCM16 单位，避免 42.67 ms 处可闻的硬截断。

每声部已有模态乘法器只在七时钟调度中的 `MULT` 使用。
利用模式 0、1、2 的 `LOAD` 与 `ENV_B` 分别计算两个反馈乘积，
在 `PHASE` 更新一个滤波器；模式 3 的 `LOAD` 计算最终包络乘积，
`ENV_B` 捕获瞬态。原来的 `MULT`/`ACC` 使用次数、32 相位累加器和
控制/音效时钟都保持不变。新模块自身没有 DSP 或 BSRAM，
音源仍占 233/256 时钟，四声部有效信号仍严格对齐。
启用击弦模型时这套复用需要至少 4 个模态槽；现有配置均为 8 或 32。

移除每声部 8 块残差 ROM 后，共释放 32 块 BSRAM；完整显示与音频工程为
86/118 块。本次成功布局使用 place=4、route=2、clock_route_order=1，
原 CST/SDC 和 hold 修复保持开启。2026-10-13 的物理报告为：

| 项目 | 使用量 / 结果 |
| --- | --- |
| Logic | 47596 / 59904 |
| Register | 18674 / 60780 |
| CLS | 26683 / 29952 |
| BSRAM | 86 / 118，释放 32 块 |
| DSP | 115.5 / 118，模型没有增加 DSP |
| audio_clk_12m288 Fmax | 14.148 MHz，要求 12.288 MHz |
| sys_clk_50m Fmax | 52.895 MHz，要求 50 MHz |
| setup / hold 违例 | 0 / 0 |

最终引脚、位流、网表和仿真证据以独立工程
`gowin/neo_guitar_procedural/verification.json` 的实际检查结果为准。

## 验证和试听

独立整数参考覆盖三个音区、四档力度、滑音、释放、同拍拨弦优先、延音、
和声、音色交叉渐变与快速重拨。另有复位复现、不同拨弦不重复噪声、
滤波状态界限、平滑尾端与到期归零的属性测试。
完整 A/B 使用旧版音源、同一演奏指令和原立体声效果器，
每版导出 136000 个真实 RTL PCM16 立体声帧，无归一化或额外软件效果。
完整综合网表再与当前 RTL 对比实际 DAC 引脚和可见 LCD 像素，
并绑定综合网表 SHA256，以排除仅在行为仿真中正确的 DSP 有符号映射问题。

三个音区的平均瞬态能量按四个独立种子校准至旧版 RMS；
单次拨弦仍会有随机差异。统计、谱图与 WAV 位于
`build/procedural_piano/`，听感和实物状态仍标为待验收。
应重点听单音的起音硬度、四音同时拨弦的噪声量、快速重拨，
并检查三音色切换、松品、音效、显示和 J17 稳定性。

冻结 RTL 仅放在 `sim/reference/piano_legacy/` 作 A/B 历史参考；旧版 PCM 表由
仿真脚本从基线 Git 提交本地恢复，不再作为本分支的版本化声音资产。
不列入任何生产 `.gprj`，不被生产 RTL 读取，参赛生产材料应排除该目录。
旧的历史验收文档仍描述旧版；它们不能作为本试验瞬态的合规证明。
独立实验工程不覆盖已验收的 `neo_guitar_radial` 下载文件。
